# DefLink — Implementation Plan

> A PDF reader that lets the user mark a highlighted passage as the **definition** (or theorem, lemma, notation…) of a **term**, then makes every other occurrence of that term hoverable to show the definition in a popover or pin it to a side stack.

This document is the source of truth for implementation. Work through the milestones in order. Each milestone has acceptance criteria; do not start the next milestone until the current one's criteria pass and `pnpm check` is green.

---

## 0. Instructions for the implementing agent

- Implement **one milestone at a time**. At the end of each, run `pnpm check` (typecheck + lint + unit tests) and fix failures before moving on.
- Keep `packages/core` **free of DOM and PDF.js dependencies**. It must be pure TypeScript, testable in Node with Vitest. All DOM / PDF.js / IndexedDB code lives in `apps/web` (and later `apps/zotero`).
- Use only the dependencies listed in §2. If another dependency seems necessary, add it, and record the reason in `docs/DECISIONS.md`.
- Prefer small, well-named modules with unit tests over large files.
- When something in this plan proves wrong in practice (e.g. a PDF.js API differs in the installed version), adapt, then record the deviation in `docs/DECISIONS.md`.
- Never commit generated PDFs larger than 200 KB. Test fixtures are generated by a script (§9).

## 1. Product scope

### 1.1 Core user flows

1. **Open a PDF** from disk (file picker or drag-and-drop). The document is identified by the SHA-256 hash of its bytes, so renaming/moving the file keeps its definitions.
2. **Mark a definition**: select text in the PDF → press `D` or right-click → "Mark as definition". A dialog opens with:
   - **Term** (prefilled with a guess, see §6.4), editable
   - **Aliases** (comma-separated, optional)
   - **Kind**: Definition / Theorem / Lemma / Proposition / Corollary / Notation / Other
   - **Label** (optional, e.g. "Def 2.3")
   - **Scope**: This document (default) / Global
   - **Case sensitive** checkbox (default off)
3. **See linked occurrences**: every occurrence of a known term on rendered pages gets a subtle dotted underline.
4. **Hover** an occurrence (300 ms delay) → popover with the definition's image crop, kind, label, source document + page, and buttons: *Pin*, *Go to source*, *Don't link here*.
5. **Pin** → the definition moves into the right-hand **Stack panel**, which persists while reading. Terms inside pinned definitions are themselves clickable (§7.4).
6. **Glossary view**: searchable list of all terms; edit term/aliases/scope, merge two terms, delete definitions.
7. **Export / import** the entire store as JSON.

### 1.2 Explicitly out of scope for v1

- OCR of scanned PDFs (detect and show a notice instead).
- Mathematical notation as terms (e.g. `𝒪_X`).
- Sync / multi-user.
- Editing the PDF file itself.

## 4. Data model

### 4.1 Types (`packages/core/src/model.ts`)

```ts
export type DefinitionKind =
  | "definition" | "theorem" | "lemma" | "proposition"
  | "corollary" | "notation" | "other";

export type Scope =
  | { type: "document"; docId: string }
  | { type: "global" };

export interface Term {
  id: string;              // uuid
  label: string;           // canonical display form, e.g. "compact space"
  aliases: string[];       // other surface forms, e.g. ["compact", "compact spaces"]
  caseSensitive: boolean;
  scope: Scope;
  createdAt: number;
  updatedAt: number;
}

/** A rectangle in PDF user-space units (origin bottom-left, as PDF.js uses). */
export interface PdfRect { x1: number; y1: number; x2: number; y2: number; }

export interface Definition {
  id: string;
  termId: string;
  kind: DefinitionKind;
  label?: string;          // "Def 2.3"
  docId: string;           // sha256 of the PDF bytes
  page: number;            // 1-based
  rects: PdfRect[];        // selection rects, one per line fragment
  text: string;            // extracted (normalized-whitespace) text of the selection
  cropId: string;          // key into the crops table
  note?: string;
  createdAt: number;
}

export interface DocumentRecord {
  id: string;              // sha256
  title: string;           // PDF metadata title, else filename
  fileName: string;
  pageCount: number;
  lastOpenedAt: number;
  hasTextLayer: boolean;
}

/** User chose "Don't link here" on an occurrence. */
export interface Suppression {
  id: string;
  termId: string;
  docId: string;
  page: number;
  /** Character offset of the occurrence start in the page's normalized text. */
  offset: number;
}

export interface Crop {
  id: string;
  blob: Blob;              // PNG; web app only. Exported as base64 data URL.
  width: number;
  height: number;
}
```

### 4.2 Dexie schema (`apps/web/src/store/db.ts`)

```ts
db.version(1).stores({
  documents:    "id, lastOpenedAt",
  terms:        "id, label, scope.type, scope.docId, updatedAt",
  definitions:  "id, termId, docId, [docId+page]",
  crops:        "id",
  suppressions: "id, [docId+page], termId",
});
```

Scope is stored as a nested object; Dexie supports indexing nested keys with dot notation.

### 4.3 Invariants

- Deleting the last definition of a term does **not** delete the term automatically; the glossary shows such terms as "orphaned" with a delete action.
- Deleting a term deletes its definitions, their crops, and its suppressions (single transaction).
- Merging term B into term A: move B's definitions to A, union aliases (plus B.label as an alias), delete B, rewrite suppressions.
- No two terms in the same scope may share a normalized surface form (label or alias). The mark-definition dialog detects collisions and offers "add as another definition of existing term X".

## 5. Text extraction and matching

### 5.1 Building page text from the text layer (`apps/web/src/pdf/pageText.ts`)

Build the matchable text **from the rendered text-layer DOM**, not directly from `getTextContent()`, so offsets map straight back to DOM text nodes for highlighting.

1. After PDF.js's `TextLayer` finishes rendering for a page, walk its `span` elements in DOM order.
2. Concatenate their `textContent` into one string. Between consecutive spans, insert:
   - `"\n"` if the next span begins a new line (detect via a vertical position change greater than half the line height, using each span's bounding box, or via the `hasEOL` flag from the corresponding text item),
   - otherwise `" "` if there is a horizontal gap larger than ~0.25 × font height,
   - otherwise nothing.
3. Record a **segment map**: for every span, `{ node: Text, start: number, end: number }` giving the span's range in the concatenated string. Inserted separators belong to no segment.
4. Output:
   ```ts
   interface PageText {
     page: number;
     raw: string;
     segments: { node: Text; start: number; end: number }[];
   }
   ```
5. Provide `rawOffsetToDom(pageText, offset): { node: Text; offset: number }`, which binary-searches the segments. Offsets falling on a separator snap to the end of the previous segment.

Also produce `hasTextLayer = raw.trim().length > 20` per page. If the first 3 pages all lack text, mark the document as having no text layer and show a non-blocking banner: "This PDF has no text layer (probably scanned). Run OCR, e.g. OCRmyPDF, to enable linking."

### 5.2 Normalization (`packages/core/src/normalize.ts`)

```ts
export interface Normalized {
  text: string;
  /** toRaw[i] = index in the raw string of normalized char i. Length text.length + 1. */
  toRaw: number[];
}
export function normalize(raw: string, opts: { caseSensitive: boolean }): Normalized;
```

Apply these steps, maintaining the `toRaw` map throughout:

1. Unicode NFKC, character by character (this splits ligatures `ﬁ → fi` and `ﬂ → fl`; one raw index maps to multiple normalized chars).
2. Remove soft hyphens (U+00AD) and zero-width characters (U+200B–U+200D, U+FEFF).
3. **Dehyphenate**: a letter, then `-` (or U+2010 / U+2011), then optional spaces, `\n`, optional spaces, then a lowercase letter → drop the hyphen and the whitespace. A hyphen followed by an uppercase letter or digit is kept, since it's probably a real compound.
4. Replace remaining `\n` and runs of whitespace with a single space.
5. Map curly quotes and apostrophes to ASCII.
6. Lowercase, unless `caseSensitive`.

Two normalized strings are produced per page: one case-folded, one case-preserving. Terms are matched against the appropriate one.

**Unit tests (required):** ligatures, soft hyphen, line-break hyphenation (both kept and removed cases), whitespace collapse, and an offset-map round-trip property test (for random substrings of the normalized text, mapping back and re-normalizing gives the same substring).

### 5.3 Tokenization (`packages/core/src/tokenize.ts`)

```ts
export interface Token { text: string; start: number; end: number; } // offsets into normalized text
export function tokenize(normalized: string): Token[];
```

A token is a maximal run matching `/[\p{L}\p{N}]+(?:['’][\p{L}]+)?/u`. Punctuation and whitespace are separators. Hyphenated compounds such as `well-defined` become two tokens (`well`, `defined`), and term patterns are tokenized the same way, so they still match.

### 5.4 Matcher (`packages/core/src/matcher.ts`)

A token-level trie with longest-match, left-to-right, non-overlapping scanning.

```ts
export interface Pattern { termId: string; tokens: string[]; caseSensitive: boolean; }
export interface Match { termId: string; start: number; end: number; } // normalized offsets

export class TermMatcher {
  constructor(patterns: Pattern[]);
  /** tokensFolded / tokensCased are tokenizations of the two normalized page strings. */
  find(tokensFolded: Token[], tokensCased: Token[]): Match[];
}
```

Algorithm:

- Build two tries (case-folded and case-sensitive), keyed by token text; terminal nodes store `termId`.
- At each token index `i`, walk both tries as far as possible and remember the longest terminal reached. If found, emit a match spanning tokens `i..j`, set `i = j + 1`; otherwise `i++`.
- On a tie in length between the two tries, prefer the case-sensitive match.
- **Light inflection** (v1): when inserting a pattern, also insert variants where the *last* token gets `s` / `es` appended, or a trailing `s` removed. Do not apply this to tokens shorter than 3 chars. Make it toggleable in settings.

**Unit tests (required):**
- "compact Hausdorff space" beats "space" and "compact"
- no match inside larger words ("ring" vs "string")
- plurals
- case-sensitive term ("Ring" vs "ring")
- matches across a dehyphenated line break
- performance: 5,000 patterns × a 10,000-token page completes in under 50 ms

### 5.5 Term index (`packages/core/src/termIndex.ts`)

```ts
export function buildMatcherForDocument(terms: Term[], docId: string): TermMatcher;
```

This includes terms whose scope is global or document-scoped to `docId`. Patterns come from `label` plus `aliases`, tokenized after normalization. Rebuild (memoized) whenever terms change. A rebuild for 5,000 terms should take under 20 ms.

### 5.6 Occurrence filtering

After matching, drop:

- matches overlapping the definition's own selection (same doc, same page, rect intersection),
- matches covered by a `Suppression` (same term, doc, page, offset),
- matches inside the popover/stack UI itself (not applicable to page text, but the same matcher is reused in §7.4).

Optional setting, off by default: **"Only link after first definition"**. When on, for document-scoped terms, ignore matches on pages before the definition's page.

## 6. Marking a definition

### 6.1 Capturing a selection

On `D` or the context-menu action:

1. Read `window.getSelection()`. Require that it is non-collapsed and lies within a single page's text layer. If it spans pages, show a toast saying "Definitions spanning pages aren't supported yet" (multi-page support is a later enhancement).
2. Collect `range.getClientRects()`, filter out zero-size rects, and merge rects on the same line (same top within 2 px).
3. Convert each rect to PDF user space with `viewport.convertToPdfPoint` (`apps/web/src/pdf/coords.ts`), producing `PdfRect[]`.
4. Text = `selection.toString()` with whitespace collapsed.

### 6.2 Dialog

This is a modal React component with the fields from §1.1. Validation:

- the term must be non-empty after normalization
- a collision with an existing term in the same scope shows an inline choice: *Add as another definition of "X"* or *Rename*

Submit writes the term (if new), the crop, and the definition in a single Dexie transaction, then triggers a matcher rebuild and re-linking of the rendered pages.

### 6.3 Image crop (`apps/web/src/pdf/crop.ts`)

1. Compute the union bounding box of `rects`, padded by 6 PDF units on each side and clamped to the page.
2. Render the page at scale 2 to an offscreen canvas (reuse the existing canvas if it is already rendered at ≥ 2× device scale).
3. `drawImage` the region into a new canvas, then `toBlob('image/png')`.
4. Store it in `crops`. Target size: under 300 KB per crop. If it's larger, re-render at scale 1.5.

The crop is the primary content in popovers, because extracted text from math-heavy PDFs is unreliable.

### 6.4 Term suggestion (`packages/core/src/suggest.ts`)

Input: the selection text, plus an optional list of `{ text, italic: boolean, bold: boolean }` runs. Font style is derived in the web app from PDF.js font info: after page render, look up `page.commonObjs.get(fontName)?.name` and treat names containing `Italic`, `Oblique`, `-It`, `Bold`, or `-Bd` as styled. If that lookup fails, pass no style info.

Heuristics, in priority order:

1. The first italic or bold run of 1–5 words.
2. Patterns (case-insensitive) such as:
   - `we (say|call) (that )?(an? |the )?(?<t>…) (is|if)`
   - `(?<t>…) is called`
   - `(an? |the )(?<t>[\w\s-]{1,40}?) is (a|an|the|said to be)`
   - `\b(Definition|Def\.)\s*[\d.]*\s*\(?(?<t>[^)]{1,40})\)?`
3. Fallback: empty, with the field focused.

Return `{ term: string; confidence: "high" | "low" }`. Unit-test each heuristic.

## 7. Linking, popover, and stack

### 7.1 Page layer structure (`PdfPage.tsx`)

```
<div class="page" style="position:relative">
  <canvas/>                                   <!-- rendered page -->
  <div class="overlay-layer"   style="pointer-events:none"/>  <!-- underlines, definition highlights -->
  <div class="textLayer"/>                    <!-- PDF.js text layer, on top, selectable -->
</div>
```

Overlays never receive pointer events, so text selection keeps working. Hover is detected by hit-testing (§7.2).

### 7.2 Rendering occurrences

For each rendered page, after the text layer is ready:

1. Build `PageText`, normalize it both ways, tokenize, and run the matcher.
2. For each match, map normalized `start/end` → raw via `toRaw` → DOM via `rawOffsetToDom`. Create a DOM `Range`, call `getClientRects()`, and convert the rects to page-relative CSS pixels.
3. Store `{ termId, rects, normalizedOffset }[]` per page in a ref, and draw a dotted-underline `div` per rect in the overlay layer.
4. Draw saved definition regions with a faint tinted background, so the user can see what they've marked.

**Lazy rendering:** only pages within ±2 of the viewport are rendered and linked, using an `IntersectionObserver`. Re-run linking when the matcher changes or the zoom level changes.

**Hit testing:** a single `mousemove` listener on the scroll container finds the page under the cursor and checks its occurrence rects. Throttle it with `requestAnimationFrame`. When the pointer is over an occurrence:
- set `cursor: help` on the container
- start a 300 ms timer to open the popover
- cancel the timer if the pointer leaves first

Also support **click** (single click with no drag and no active selection) to open the popover immediately. This matters for touch devices and dense text.

### 7.3 Popover (`features/popover`)

This uses Floating UI, anchored to the hovered rect, with `flip` and `shift` middleware and a max width of 520 px. Contents:

- a header with the term label, kind badge, and label ("Def 2.3")
- the crop image (`URL.createObjectURL`, revoked on close)
- the source line: document title (or "this document"), plus "p. N"
- if the term has several definitions, the current document's definitions first, then others under "Other definitions (k)", collapsed
- actions: **Pin** (`P`), **Go to source** (`G`; scrolls to the page and flashes the region), **Don't link here**, **Edit**

The popover stays open while the pointer is over the popover itself, and closes 200 ms after the pointer leaves both the anchor and the popover, or immediately on `Esc`.

### 7.4 Stack panel (`features/stack`)

- A right-hand collapsible panel, 360 px wide by default and resizable.
- Pinned definitions appear as cards: crop, header, source, ✕ to unpin, ↑/↓ to reorder.
- **Nested linking**: under each card, run the matcher over the definition's stored `text`. Show the matched terms as chips (deduplicated, excluding the card's own term). Clicking a chip pins that term's best definition directly below the current card.
- Breadcrumb: the order in which cards were opened, shown as a compact trail at the top.
- Stack state is persisted per document in `localStorage` (just the list of definition IDs).

### 7.5 Glossary (`features/glossary`)

- A modal or route showing a table of terms: label, aliases, scope, number of definitions, last updated.
- Search across label, aliases, and definition text.
- Row actions: edit (label, aliases, scope, case sensitivity), merge into… (choose a target term), delete.
- Bulk select → delete.
- Shows orphaned terms (no definitions).

## 8. Export / import (`packages/core/src/exportFormat.ts`, `apps/web/src/store/repo.ts`)

```ts
interface ExportFileV1 {
  format: "deflink";
  version: 1;
  exportedAt: string;           // ISO
  documents: DocumentRecord[];
  terms: Term[];
  definitions: Definition[];
  crops: { id: string; dataUrl: string; width: number; height: number }[];
  suppressions: Suppression[];
}
```

- **Export** downloads `deflink-YYYY-MM-DD.json`.
- **Import** validates the schema with a hand-written type guard (no extra dependencies). Conflict policy: records with the same `id` are skipped, unless "overwrite" is chosen. Terms that collide on surface form within the same scope are merged into the existing term.
- Unit-test the validation and the merge logic in core, with crop blobs abstracted out.

### M9 (optional): Zotero plugin adapter
> **Verify every Zotero API named here against the current Zotero plugin documentation and the source of the installed Zotero version before writing code.** The reader internals are not a stable public API.

- `apps/zotero`: a bootstrap plugin (`manifest.json`, `bootstrap.js`) bundled with esbuild, reusing `packages/core` unchanged.

- **Accept:** in Zotero, a user can mark a definition, see underlines, and hover for a popover on a real paper.

## 11. Performance budgets

| Operation | Budget |
|---|---|
| Matcher rebuild, 5,000 terms | < 20 ms |
| Linking one page (extract + normalize + match + overlay) | < 30 ms typical, < 80 ms worst |
| Hover hit test | < 1 ms per mousemove |
| Crop generation | < 300 ms |
| Memory | Pages more than 5 away from the viewport release their canvas |

If linking exceeds the budget, move normalize + tokenize + match into a Web Worker. The core package is DOM-free precisely so this is easy to do.

## 12. Known risks and mitigations

| Risk | Mitigation |
|---|---|
| Common-word terms ("field", "ring", "normal") over-link | Document scope by default, case sensitivity, suppressions, "only after first definition", underline toggle |
| Text-layer span order doesn't follow reading order in odd PDFs | Matching is per contiguous span sequence. Accept occasional misses, and log them in debug mode |
| PDF.js API changes between versions | Pin the exact `pdfjs-dist` version, and confine PDF.js calls to `apps/web/src/pdf/` |
| Font-style detection fails | Suggestion falls back to patterns, then manual entry |
| Large IndexedDB usage from crops | Show the store size in settings, and offer "re-compress crops" (re-encode as WebP at 0.8 quality) |
| Zotero internals change | All internal access is in `readerBridge.ts`, with a feature-detect check that degrades to "mark only, no linking" |
